Distribuição por cliente · arquitetura proposta

Especialistas com memória corporativa

O FDE publica cada especialista com uma identidade própria na organização. O assistente de projeto prepara o relatório semanal do MVP. Cada especialista responde com evidências já processadas na instalação. O Temporal coordena o trabalho que precisa continuar depois da conversa.

C1 / Contexto

Pessoas, produto e fontes

Cada cliente recebe uma instalação pxOS. O PM conversa com um especialista ou revisa uma entrega. O FDE controla a definição publicada de cada especialista.

C2 / Contêineres

O que roda em cada instalação

O Temporal agenda e mantém o estado dos processos. Os workers executam as tarefas. O kernel monta o especialista com o Google ADK a partir da versão publicada. O FDE acompanha as execuções na Temporal Web UI.

Ana, de Sales Ops, ilustra essa identidade. Duas pessoas conversam com a mesma Ana em históricos privados. O FDE define as instruções, as ferramentas e a agenda na configuração da distribuição. O kernel registra a versão aprovada em cada execução. Pessoas e workflows se dirigem ao mesmo especialista. A autorização considera quem faz a solicitação e quem pode receber o resultado.

C3 / Componentes

Por dentro do worker Python

Duas responsabilidades usam o mesmo SDK do Temporal: sincronizar evidências de forma incremental e conduzir entregas até a revisão humana. As integrações externas rodam em Activities.

Fluxos no tempo

Diagramas de sequência

As setas mostram a ordem das mensagens. Cada sequência identifica quem toma a iniciativa, quem acessa o banco e onde o processo pode esperar.
